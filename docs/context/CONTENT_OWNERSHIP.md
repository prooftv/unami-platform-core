# Content Ownership

Phase 17B deliverable. Constitutional document.
This boundary is frozen before any CMS code is written.
Do not contradict it. Do not work around it. If a new content type is needed, classify it here first.

---

## The Fundamental Separation

```
SANITY                              SUPABASE
──────────────────────────          ──────────────────────────────────
Editorial                           Operational
Curated                             Records
Presentation                        Evidence
Pages                               Participation
Media                               Workflows
SEO                                 Institutional memory
Landing pages                       Commercial
Stories                             Analytics
                                    Intelligence
```

These are not competing systems. They are complementary systems with distinct responsibilities.
Neither crosses into the other's domain. Ever.

## Immutability Rules

| Content Type | Immutable? | Rule |
|---|---|---|
| Broadcasted moment | ✅ Yes | Once `status = 'broadcasted'` — no edits, no deletes. Enforced in Edge Functions. |
| Broadcast record | ✅ Yes | Delivery records are never modified after creation. |
| Audit log entries | ✅ Yes | Append-only. Never modified. |
| Evidence attachments | ✅ Yes | Added only. Never removed. |
| Participation log entries | ✅ Yes | Append-only. No personal data. |
| Sanity published content | ⚠️ Versioned | Sanity maintains document history via `_rev`. Published content can be updated — the revision identifier changes. |
| Draft moments | ❌ No | Editable until broadcasted. |
| Sponsor / campaign records | ❌ No | Editable by authorised admin roles. |
| System settings | ❌ No | Editable by superadmin only. |

## Editorial vs Operational

The distinction that matters most.

**Editorial content** is curated by a human for presentation. It is written once (or updated deliberately). It has SEO value. It tells a story. It belongs in Sanity.

**Operational content** is generated by the system or by user action. It is a record of something that happened. It has audit value. It belongs in Supabase.

| Content | Editorial or Operational? | Owner |
|---|---|---|
| "About Moments" page | Editorial | Sanity |
| A moment published by an admin | Operational | Supabase |
| A sponsor's editorial profile | Editorial | Sanity |
| A sponsor's commercial record (budget, tier, status) | Operational | Supabase |
| A campaign landing page | Editorial | Sanity |
| A campaign's delivery data (spend, reach, analytics) | Operational | Supabase |
| A help article | Editorial | Sanity |
| A moderation decision | Operational | Supabase |
| An authority's editorial profile | Editorial | Sanity |
| An authority's operational record (audit log, stats) | Operational | Supabase |
| Homepage hero image | Editorial | Sanity |
| A moment's media attachment | Operational | Supabase Storage |

## Generated vs Curated vs Operational

Three content modes. Each has a different owner and a different lifecycle.

**Generated** — produced by the system from underlying records. Never edited directly.
Examples: broadcast delivery reports, analytics summaries, participation counts, Layer 5 certificates.
Owner: Supabase (data) + Edge Functions (generation).

**Curated** — written by a human for presentation. Updated deliberately.
Examples: homepage hero, featured stories, help articles, about page, sponsor editorial profiles.
Owner: Sanity.

**Operational** — created by user action or system process. Records of events.
Examples: moments, broadcasts, subscriptions, moderation decisions, audit logs.
Owner: Supabase.

## The apps/web Composition Model

`apps/web` is the composition layer. It does not own content — it presents it.

```
Page                    Sanity query?       Supabase query?
──────────────────────  ─────────────────   ───────────────────────
/                       ✅ homePage          ✅ featured moments
/feed                   ❌                  ✅ moments feed
/moments/[id]           ❌                  ✅ moment detail
/region/[region]        ❌                  ✅ moments by region
/category/[category]    ❌                  ✅ moments by category
/search                 ❌                  ✅ moments search
/subscribe              ❌                  ❌ (static UI)
/about                  ✅ aboutPage         ❌
/help                   ✅ helpArticle[]     ❌
/privacy                ✅ privacyPage       ❌
/terms                  ✅ termsPage         ❌
/sponsors               ✅ sponsorPage[]     ✅ sponsor operational data
/campaigns              ✅ campaignPage[]    ✅ campaign operational data
/authority              ✅ authorityPage[]   ✅ authority operational data
```

Pages that query both sources compose them in the server component. Neither source is aware of the other.

## What Never Crosses the Boundary

These rules are absolute. No exceptions.

**Sanity never contains:**
- Moment records
- Broadcast data
- Subscriber data
- Moderation decisions
- Analytics events
- Participation submissions
- Evidence records
- Audit logs
- Any operational data

**Supabase never contains:**
- Homepage composition
- Editorial long-form content
- SEO metadata
- Help articles
- Privacy or terms content
- Editorial media assets
- Navigation structure

**Edge Functions never contain:**
- Sanity queries
- Sanity write operations
- Any reference to `@sanity/client`

**apps/web never contains:**
- Direct Supabase client (`@supabase/supabase-js`)
- Direct database queries
- Sanity write operations
- Any content that belongs in Sanity but is hardcoded in JSX

## The Test for Every New Content Type

Before adding any new content type, answer:

1. Is it written by a human for presentation? → Sanity
2. Is it a record of something that happened? → Supabase
3. Is it generated from underlying records? → Supabase (data) + Edge Function (generation)
4. Does it have SEO value? → Sanity
5. Does it have audit value? → Supabase
6. Is it immutable once created? → Supabase, with immutability enforced in Edge Functions

If the answer is ambiguous — it is almost certainly Supabase. Sanity is for editorial content only.
When in doubt, ask before writing.
